# Strategic Soccer на сервере

Пакет для серверных прогонов (цели и план — `docs/server_plan.md`). Нужны Linux, g++ 9+ (или clang++), python3 3.7+, `lscpu`. Сеть не нужна.

## Запуск

```bash
tar xzf soccer_server_*.tgz && cd soccer_server
chmod +x run_server.sh build_linux.sh
./run_server.sh smoke                      # 5–15 минут: сборка, тесты, все этапы в малом виде -> results_smoke/
tmux new -s soccer                         # или screen; без них — nohup (ниже)
./run_server.sh all 2>&1 | tee -a run.log  # все этапы по порядку -> results/
# без tmux:  nohup ./run_server.sh all > run.log 2>&1 &
```

Если скрипт пишет `bad interpreter` / `$'\r'` — файлы попали с переводами строк Windows: `sed -i 's/\r$//' *.sh`.

Каждый этап продолжается с места остановки: после обрыва повторить ту же команду. Отдельные этапы: `./run_server.sh curves ladder`. Ход — `tail -f results/logs/<этап>.log`, начало и конец этапов — `results/logs/stages.log`.

Настройки (переменные окружения): `JOBS` — одновременных поисков (по умолчанию — число физических ядер, доступных процессу: у сервера с EPYC 7763 включены 40 логических из 128, около 35 физических — считается по `lscpu` и маске процесса), `LEVELS` — уровни эталона `ширина x глубина`, `DEPTHS` — глубины лестницы, `BUDGETS` — секунды для кривых. Пример: `JOBS=30 ./run_server.sh curves`.

Если сервер общий — `JOBS` меньше числа свободных ядер; загрузку смотреть `uptime` / `htop`.

## Этапы

| Этап | Что делает | Время (оценка) | Файл |
| --- | --- | --- | --- |
| `info` | описание машины | секунды | `machine.json` |
| `build` | сборка `-O2 -march=native`, 4 набора тестов | 3–5 мин | `logs/build.log` |
| `scaling` | глубина 3 и 4, потоки 1, 2, 4, … до физических и логических ядер; ход, значение и раскрытия должны совпасть | 2–4 ч | `scaling_d3.csv`, `scaling_d4.csv` |
| `calib` | одни и те же поиски по одному и все сразу: насколько процессы тормозят друг друга | 10–20 мин | `calib_d3.csv` |
| `curves` | глубина от времени, 30…3840 с, по процессу на поиск | ~1,5 ч | `curves.csv` |
| `ladder` | глубины 1–6 из позиции и после хода бота, глубина за глубиной; не уложилась в тайм-аут — глубже не идёт | часы | `ladder.csv` |
| `consistency` | статика против перебора: 600 позиций из партий (`games/`) + v4; статика и её составляющие, V(d) d1–d4 для всех, d5 — 100, d6 — 30; лист главной линии глубины 3 против поиска из него | 10–14 ч | `cons_*.csv`, `cons_report.txt` |
| `candidates` | кандидаты эталона: ходы набора, ходы пользователя, планы из `curves`/`ladder`, решения корня широкого поиска | ~1 ч | `ref_candidates.csv`, `ref_outcomes.csv` |
| `verify` | каждый кандидат на уровнях `8x3 … 8x6` (ширина × глубина) | ночь и больше | `ref_values.csv` |
| `report` | таблица «кандидат × уровень», ранги, устоялся ли порядок, ошибка ходов ботов | секунды | `ref_report.txt`, `ref_summary.csv` |
| `pack` | архив результатов | секунды | `soccer_results_<хост>_<дата>.tgz` |

Время — грубая оценка с машины на 2 ядра; d5–d6 и широкие уровни могут не уложиться в тайм-аут (4–6 ч на поиск), тогда в CSV строка `timeout`.

Свои ходы для эталона — в `tools/server/user_moves.txt` (строки `id_позиции|ходы`, как в `suite_moves.txt`), до этапа `candidates`.

## Что привезти

`soccer_results_*.tgz` (этап `pack`, можно и посреди прогона) — положить в `C:\temp\strategic_soccer\build\server_<дата>\`.
