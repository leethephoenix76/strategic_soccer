# Архитектура кода

Код разделён на **движок** (правила игры, без зависимостей от Windows) и **интерфейс** (Win32/GDI поверх движка). Движок спроектирован так, чтобы на нём можно было строить бота: перебор, Монте-Карло, обучение нейросети.

## Структура

```
src/
  engine/              правила игры: только стандартный C++17, без Windows
    types.h            константы поля и команд, Cell, вспомогательные функции
    rng.h              детерминированный генератор случайных чисел (живёт в состоянии)
    state.h/.cpp       GameState — полное состояние матча; NewMatch, PlayerAt
    actions.h          Action (Place, Move, Attack, Pass, Shot, EndTurn), ActionError
    events.h           Event — что произошло (перехват, гол, предупреждение о тупике...)
    rules.h            ПУБЛИЧНЫЙ API движка
    rules.cpp          Validate / Apply / LegalActions, структура хода, рестарты
    movement.cpp       инерция и блокировки (MoveDestinations), расстановка (CanPlace)
    ball.cpp           полёт мяча, перехваты, ауты, вратарь в створе, прогноз траектории
    duel.cpp           борьба за мяч: отбор у владельца и выковыривание
    shot.cpp           удар по воротам
    deadlock.cpp       детектор тупика (BallSealedBy)
    outcomes.h         явные случайные исходы действий (Outcome)
    notation.h/.cpp    нотация: клетки, действия, исходы, позиции, записи партий (docs/notation.md)
    internal.h         внутренние функции, общие для .cpp движка (не API)
  bot/                 бот: только стандартный C++17, зависит от engine
    bot.h/.cpp         Bot: план хода команды из поиска (goal_dfs_search.h), перепланирование после
                       случая, бюджет времени на командный полуход; LineupAction — расстановка «ромб»
    bot_registry.h/.cpp  коллекция ботов: именованные настройки Bot для игры, матчей и записи партий
    goal_dfs_search.h/.cpp поиск по цели «свой гол минус чужая контратака» (bot_design.md, §3):
                       точный (goal-team-moves) и селективный — луч с альфа-бетой или дерево по PUCT;
                       статика PositionEstimate (bot_design.md, §4)
    goal_episode.h/.cpp  эпизод цели: своя атака, чужая контратака, гол, конец эпизода
    goal_bounds.h/.cpp   строгие границы значения состояния
    team_moves.h/.cpp    все различные состояния от законных последовательностей перемещений в ходе
    pass_pruning.h/.cpp  строгий частный сертификат потери мяча после паса
    episode.h/.cpp     эпизод атаки по гонке к воротам: 1 в 0, 2 в 1, игроки вне эпизода и их правило
    episode_value.h/.cpp  таблица эпизода: минимакс только по участникам (1 в 0, 2 в 1), лучшая вероятность гола
                       (опции: движущийся фронт соперников вне таблицы, пас на ход; решение корня для бота)
    ball_plan.h/.cpp   планы мяча и их участники, цепочки, маршруты мяча с движущимся фронтом
                       (инструменты замера ssbot ball-plans / ball-chains / ball-routes / route-tables)
    ball_race.h/.cpp   кто первым достигает свободного мяча: нижняя и гарантированная оценки, Taken/Restart/Contested;
                       нижние границы гола при владении: выход 1 в 0, 2 в 1
    race.h/.cpp        гонка за свободным мячом: точная игра двоих, альфа-бета (~1 мс на 8 полуходов)
    reach.h/.cpp       досягаемость с инерцией: за сколько ходов игрок доберётся до каждой клетки
    reach_front.h/.cpp  чередующиеся области восьми игроков, первые прибытия и границы контакта
    value.h/.cpp       таблица владения T(c) по клетке мяча (вкомпилирована, possession_table_data.cpp)
    hash.h/.cpp        64-битный хеш состояния для таблиц транспозиций
  ui/                  интерфейс Win32
    app.cpp            WinMain, окно, перевод щелчков мыши в действия движка; бот за любую команду
                       (бот из коллекции, bot_registry.h — щелчок по кнопке команды перебирает ботов;
                       думает в отдельном потоке; имя бота — в тегах партии),
                       запись партии, открытие и просмотр сохранённых партий
    renderer.h/.cpp    отрисовка GDI (с двойной буферизацией)
    layout.h           размеры клетки, кнопки, попадание щелчка
    text.h/.cpp        тексты сообщений для событий и ошибок
    ui_state.h         состояние интерфейса: выбранный игрок, режим паса
tests/
  engine_tests.cpp     тесты движка (переносимые, без Windows)
  bot_tests.cpp        тесты поиска (точный против полного перебора последнего хода, селективный, дерево),
                       гонки, эпизода, симметрии статики и бота
  ball_race_tests.cpp  решатель гонки против точного перебора порядков ходов
  two_vs_one_tests.cpp граница 2 в 1 (и 1 в 0) против точного перебора урезанной игры
tools/
  ssbot.cpp            консольная утилита: партия бот против бота, поиск и статика на позиции, проверка записи
legacy/                исходный main.cpp и его промежуточные версии — для справки
docs/                  документация
```

Зависимости идут в одну сторону: `ui → bot → engine`, `tools → bot`. Интерфейс использует бота (`Bot`) как игрока за любую команду. Движок ничего не знает об интерфейсе и ничего не выводит на экран.

## Состояние: `GameState`

`GameState` — простой копируемый тип-значение: без указателей и глобальных переменных. Копия стоит порядка сотен байт. Всё, что нужно правилам, лежит внутри:

| Поле | Смысл |
| --- | --- |
| `players[8]` | игроки 0–3 White, 4–7 Black: `pos` — текущая позиция, `turnStart` — позиция на начало хода, `prevTurnStart` — на начало предыдущего хода; `moved`, `attacked`, `attackDir` |
| `ball` | `pos`, `vel` (скорость катящегося мяча), `dec` (торможение), `holder` (игрок или `kNoPlayer`), `stepPhase` (мяч делает шаг на каждом втором End Turn), последнее касание (`lastTouchTeam`, `lastTouchWasPass`), атакующая команда эпизода `attackTeam` |
| `phase` | `Lineup`, `Play`, `Finished` |
| `teamToMove`, `score[2]`, `halfTurns` | ходящая команда, счёт, число полуходов (время = `halfTurns / 2` минут) |
| `ballPlayed`, `committed` | команда уже играла мячом в этом ходе; в этом ходе было случайное событие (Take Back невозможен) |
| `sealHistory[2]` | история запирания мяча для детектора тупика |
| `turnId` | меняется при начале каждого нового хода или рестарта |
| `rng` | генератор случайных чисел |

Скорость игрока с прошлого хода — `Velocity() = turnStart − prevTurnStart`, смещение в текущем ходе — `Displacement() = pos − turnStart`.

## Действия и события

Ход команды — последовательность действий, заканчивающаяся `EndTurn`:

```cpp
GameState s = NewMatch(seed);
EventLog events;
ActionError err = Apply(s, Action::Move(2, {6, 11}), &events);
if (err != ActionError::None) { /* действие запрещено, состояние не изменилось */ }
for (const Event& e : events) { /* что произошло: перехват, гол, рестарт... */ }
```

- `Validate(s, a)` — проверка без изменения состояния.
- `Apply(s, a, &events, &outcome)` — проверка и применение. Случайный исход выбирается из `Outcomes(s, a)` одним числом из `s.rng`; если передан `outcome`, туда записывается выпавший исход (так ведётся запись партии).
- `Outcomes(s, a)` — все случайные исходы действия с вероятностями (сумма 1); у неслучайного действия один исход `Certain`.
- `ApplyOutcome(s, a, o)` — применение действия с заданным исходом, без генератора.
- `OutcomesUnchecked`, `ApplyUnchecked` — то же без проверок, для перебора (действие должно быть из `LegalActions`).
- `LegalActions(s)` — все допустимые действия ходящей команды. Это основа для бота: перебор, случайные доигровки, маска выходов нейросети.

### Случайные исходы

Каждое случайное событие правил — выбор из конечного списка исходов (`outcomes.h`):

| Действие | Исходы |
| --- | --- |
| пас, шаг свободного мяча на End Turn | `BallThrough`; `Intercepted` игроком; `Deflected` игроком в клетку (каждая клетка рикошета — отдельный исход) |
| отбор, выковыривание | `Won`; `KnockedAway` в клетку; `Kept` |
| удар | `Goal`; `Caught`; `Parried` в клетку (15 клеток) |

Вероятности те же, что в правилах (`game_model.md`). Перебор усредняет по всем исходам точно, без сэмплирования.

## Запросы к позиции

Функции из `rules.h`, которыми пользуются и интерфейс, и бот:

| Функция | Что даёт |
| --- | --- |
| `MoveDestinations(s, player)` | клетки, куда игрок может пойти (инерция, блокировки, ограничение после атаки) |
| `CanPlace(s, player, cell)` | можно ли поставить игрока при расстановке |
| `GetAttackKind(s, player)` | можно ли атаковать: `Tackle`, `Poke` или `None` |
| `CanPassTo(s, cell)` | допустима ли цель паса |
| `PassReachesOwnKeeper(s, cell)` | пас докатится до своего вратаря (нарушение) |
| `PredictBallPath(s)`, `PredictPassPath(s, cell)` | траектория мяча без учёта перехватов |
| `ShotProbability(s, shooter)` | вероятность гола при ударе |
| `BallSealedBy(s, team)` | заперт ли мяч командой (тупик) |

Формулы правил для заданных клеток — для моделей бота, которые расставляют игроков гипотетически; действия движка пользуются ими же, поэтому формулы живут в одном месте:

| Функция | Что даёт |
| --- | --- |
| `MovePathBlocked(start, target, blockers, count)` | блокировка пути списком занятых клеток локального квадрата |
| `AttackDirectionAllowed(a, ball, v, d)` | атака не против скорости с прошлого хода и не против смещения в этом ходе |
| `TackleChance(holder, attacker, team)`, `kKnockAwayChance` | вероятность отобрать мяч, вероятность выбить его |
| `InterceptionWeight(d)` | p(d) игрока на расстоянии d от линии мяча: перехват p², рикошет p − p² |
| `OpenShotProbability(cell, team)`, `BlockFactor(d)` | удар без блокирующих и множитель за каждого блокирующего |
| `ParryCells(team, cells)`, `kParryCells` | клетки, куда отлетает отбитый удар (равновероятно) |

## Случайность и детерминизм

Все случайные события `Apply` берутся только из `GameState::rng` (одно число на случайное действие). Поэтому:

- одинаковые seed и последовательность действий дают одинаковую партию (повторы, отладка, тесты);
- копия состояния воспроизводит те же исходы. Перебор поэтому не пользуется `Apply`, а перечисляет исходы через `Outcomes` / `ApplyOutcome` — иначе он «знал бы будущие кубики»;
- запись партии хранит исходы явно (`{int B2}`, `{won}`…), так что она проигрывается и без seed;
- вероятности исходов можно получать аналитически (`ShotProbability`) — это пригодится для оценочной функции бота.

## Бот

Устройство и решения — в [bot_design.md](bot_design.md); история до 26.10.2026 — в [archive/bot_design_full.md](archive/bot_design_full.md).

`Bot` (`bot.h`) — игрок за команду: в расстановке ставит «ромб» (`LineupAction`), в игре вызывает `GoalDfsSearch::Search` и выполняет план хода до первого случайного действия или End Turn, после случая ищет заново. Время — на командный полуход (`BotOptions::timeLimit`), делится между оставшимися решениями хода. Опытная опция `BotOptions::episodeTableMoves` (бот `-pkr-etm-`, 02.11.2026): в начале хода с мячом в эпизоде 1 в 0 / 2 в 1 план хода берётся из решения корня таблицы эпизода (`EpisodeTablePlan`), иначе — из поиска.

`GoalDfsSearch` (`goal_dfs_search.h`) — один класс, режимы задают флаги `GoalDfsOptions`:

- **точный** (`selectiveWidth = 0`): все законные решения, строгие границы, перезаписываемая таблица позиций, ограничение памяти; `completeTurns` и `groupMovements` — глубина по командным ходам и склейка перемещений (`team_moves.h`). Это эталон `goal-team-moves`;
- **селективный луч** (`selectiveWidth > 0`): кандидаты — 8 состояний перемещений и действий с мячом по статике, альфа-бета, таблица транспозиций, итеративное углубление по командным ходам;
- **дерево** (`selectiveTree`): основной луч до 16 кандидатов на узел, дополнительные кандидаты по категориям мяча и одиночные действия в корне; PUCT, исходы движка, склейка позиций и сохранение дерева между поисками.

Имена и настройки доступных ботов — в [bot_design.md](bot_design.md), §5, и через `ssbot bots`; удалённые варианты — в [archive/bot_inventory.md](archive/bot_inventory.md). Команды `ssbot` и их параметры выводит `ssbot` без аргументов. Основные команды: `selfplay`, `search`, `estimate`, `goal-static`, `attack-episode`, `goal-team-moves`, `team-moves`, `replay`, `positions` (начала полуходов записи), `stats`, `timing`, `ball-race` (решатель гонки за свободным мячом: позиция подробно или все свободные мячи партий), `episode-value` (таблица эпизода), `table-bench` (пересчёт таблиц, снятых `search --table-dump`). У `search` ключ `--threads N` — параллельный перебор (значения и ход не зависят от числа потоков), `--profile-root` — время решений корня и доля пакетных оценок. Зафиксированные позиции и сравнение ботов — в [bot_test_suite.md](bot_test_suite.md).

`ssbot reach-front "<position>" [--turn-depth N]` отдаёт кадры геометрической карты в JSON. См. [bot_design.md](bot_design.md), §4.7.

## Сборка и тесты

Под Linux (сервер): `./build_linux.sh [--tests]` собирает `build/linux/ssbot` и тесты; серверные прогоны — `run_server.sh` (этапы, продолжение после обрыва; `README_SERVER.md`), `tools/server/bench.py` (масштабирование, калибровка, кривые, лестница), `tools/server/reference.py` (эталон: кандидаты, проверка по уровням ширина × глубина, отчёт), `tools/server/consistency.py` (статика против перебора на выборке позиций из партий), общие функции `tools/server/sslib.py`; `ssbot search --width W` — ширина луча вместо своей у бота ([server_plan.md](server_plan.md)). `build_msvc.bat` собирает `build\soccer.exe` (игра), `build\engine_tests.exe` (тесты движка), `build\bot_tests.exe` (тесты бота, с ключом `--bot-tests`) и `build\ssbot.exe` (утилита бота), `build\ball_race_tests.exe` (тесты решателя гонки, ~1 мин), `build\two_vs_one_tests.exe` (граница 2 в 1 против точного перебора; аргументы: число позиций и горизонт, по умолчанию 200 и 2). Код бота всегда собирается с `/O2` (и в игре тоже): без оптимизации перебор в разы медленнее. В VS Code:

- `Ctrl+Shift+B` — задача **Build**;
- задача **Run engine tests** — собрать и прогнать тесты;
- `F5` — **Debug game** или **Debug engine tests**.

Тесты движка не зависят от Windows, поэтому собираются любым компилятором C++17.
