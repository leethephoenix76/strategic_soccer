**Ошибка хода бота (120 с)** = лучший − ход бота, сумма по 10 позициям: 0,79 (8x3), 0,37 (8x4), 0,83 (16x3) — зависит от уровня больше, чем от бота. Основной вклад — g7_03w (0,21 / 0 / 0,30), g2_148w (0,27 / 0 / 0,35), g9_04b (0,19 / 0,19 / 0,08), g9_16b (0,09 / 0,11 / 0,08).

**Смещение метода.** Кандидат, обрезанный пасом внутри хода, проверяется поиском, в корне которого — сама сторона хода (досчитывает свой ход); кандидат, кончающийся `end`, — поиском, в корне которого соперник. Асимметрия корня (0,04–0,17, волна 2) даёт первым преимущество. В g7_03w, g9_16b, g8_47b все три лучших при 16x3 — кандидаты с пасом внутри хода, лучше лучших `end` на 0,2–0,3 (g7_03w: 0,48 против 0,19); где кандидатов с пасом нет (g7_02b, g9_04b, g9_17w) — вопроса нет. Часть этой разницы — метод, а не игра.

## Что менять в методе

1. Все кандидаты оценивать в одной точке: после конца хода, соперник в корне. Для кандидата с пасом — по каждому исходу паса досчитать ход тем же поиском (как сделал бы бот), затем ход соперника; либо, наоборот, всем кандидатам дать сторону хода в корне (значение поиска из корня, где корень ограничен действиями кандидата).
2. Сравнивать уровни одной чётности (8x3, 16x3, 8x5), а не соседние глубины.
3. Пока внутренний узел беднее корня (замер 04.11), «шире и глубже» тем же лучом не сходится к истине; эталон по лучу — ориентир, а не истина. Для эпизодов (g7_30b, g7_38b, g2_148w) — точный перебор по участникам (таблица эпизода).

`8x5` на текущем методе — 16 из 181 за 6 ч (g7_38b после пасов — тайм-ауты); предлагается остановить и пересчитать по пп. 1–2.
